Protect scores the **caller** of an HTTP request. Use it to detect and
deny VPNs, proxies, Tor exit nodes, hosting (data center) IPs, and other
high-risk networks.

To score the **hosts a Guard call would contact** – outbound destinations on
an agent tool call – see
<Link.Page href="/guards/threat-detection">Threat detection</Link.Page>.

You can enforce inbound IP analysis in two ways:

- A <Link.Page href="/filters">filter</Link.Page> rule denies matching traffic
  together with your other Arcjet rules.
- The `ip` field on the decision lets you customize the response in your
  handler, including the `ip.threat` assessment when it is present.

IP analysis fields need data from the Arcjet Cloud API, so they are populated
when `protect()` calls the API. For more information about each field, see
IP analysis in the SDK reference for your framework.

## IP threat signals

Arcjet labels each client IP with one or more network types and, when
available, a threat intelligence assessment.

| Signal | Filter field | JavaScript | Python | Go |
| --- | --- | --- | --- | --- |
| VPN | `ip.src.vpn` | `ip.isVpn()` | `ip.is_vpn()` | `ip.IsVPN` |
| Proxy | `ip.src.proxy` | `ip.isProxy()` | `ip.is_proxy()` | `ip.IsProxy` |
| Tor | `ip.src.tor` | `ip.isTor()` | `ip.is_tor()` | `ip.IsTor` |
| Hosting or data center | `ip.src.hosting` | `ip.isHosting()` | `ip.is_hosting()` | `ip.IsHosting` |
| Privacy relay | `ip.src.relay` | `ip.isRelay()` | `ip_details.is_relay` | `ip.IsRelay` |
| Known abuse | None | `ip.isAbuser()` | `ip.is_abuser()` | `ip.IsAbuser` |
| Service name | `ip.src.service` | `ip.service` | `ip_details.service` | `ip.Service` |
| ASN type | `ip.src.asnum.type` | `ip.asnType` | `ip_details.asn_type` | `ip.ASNType` |

`asnType` is one of `isp`, `hosting`, `business`, or `education`. Real users
are more often on an ISP or business network than on a hosting provider.

A hosting label means the IP belongs to a hosting provider. That raises the
chance the client is automated, but an API used by other servers can see
legitimate hosting IPs.

VPN, proxy, and Tor labels mean the client is hiding its origin. People use
VPNs for privacy or work, so a VPN match alone is not proof of abuse. Treat it
as a risk signal and decide based on the route.

Privacy relays such as Apple Private Relay are paid services tied to an
account. They are less likely to be automated than an open proxy. Don't deny
`ip.src.relay` unless you intend to block those clients.

Filters do not read `ip.threat`. To deny on risk level, reputation, activity,
or entity, inspect the decision after `protect()`.

When threat intelligence is available, the JavaScript SDK exposes it as
`decision.ip.threat`, the Python SDK as `decision.ip_details.threat`, and the
Go SDK as `decision.IP.Threat`. Responses without an assessment omit it.

Python uses snake_case for the same names. Go uses PascalCase. The following
sections list every field Arcjet exposes and the string values you can match
on.

### Threat assessment fields

| Field | JavaScript | Python | Go |
| --- | --- | --- | --- |
| Risk level | `riskLevel` | `risk_level` | `RiskLevel` |
| Confidence | `confidence` | `confidence` | `Confidence` |
| Reputation | `reputation` | `reputation` | `Reputation` |
| Trusted infrastructure | `isSafe` | `is_safe` | `IsSafe` |
| Network types | `networkTypes` | `network_types` | `NetworkTypes` |
| Activities | `activities` | `activities` | `Activities` |
| Entities | `entities` | `entities` | `Entities` |
| Entity name | `entityName` | `entity_name` | `EntityName` |
| Service | `service` | `service` | `Service` |

`isSafe` / `is_safe` / `IsSafe` is a boolean. When it is `true`, Arcjet
treats the IP as trusted infrastructure: `riskLevel` is `none`, and threat
activities are suppressed. Network types and entity labels can still appear
for context.

`entityName` and `service` are free-form strings when Arcjet identifies a
specific client or provider (for example a scanner or crawler name). They
are empty when unidentified. Compare them only when you know the exact
value you want to allow or deny.

For outbound destination scoring on Guard policies, Rego reads a subset of
these fields under `input.signals.ip_threat.<id>`. For more information, see
<Link.Page href="/guards/threat-detection">Threat detection</Link.Page>.

#### Risk level

`riskLevel` is the overall assessment for the IP:

| Value | Meaning |
| --- | --- |
| `none` | No elevated risk, or the IP is trusted infrastructure (`isSafe`) |
| `low` | Weak signals only, such as a network type without confirmed abuse |
| `medium` | Observed activity or combined signals that warrant caution |
| `high` | Strong abuse signals, such as brute force or multiple activities |
| `critical` | Severe signals, such as botnet, exploit, or malware activity |

Name the levels you deny. Do not compare with `>= "high"` – string sorting
does not match the risk order.

#### Confidence

`confidence` is how sure Arcjet is in the assessment:

| Value | Meaning |
| --- | --- |
| `low` | Limited evidence for the classification |
| `medium` | Moderate evidence |
| `high` | Strong evidence |

Require `medium` or `high` before you deny on a public page.

#### Reputation

`reputation` is the threat-intelligence label for the IP:

| Value | Meaning |
| --- | --- |
| `malicious` | Strongly associated with abuse |
| `suspicious` | Elevated risk without a confirmed malicious label |
| `known` | Previously observed, without a malicious or safe verdict |
| `safe` | Trusted infrastructure (also sets `isSafe`) |
| `benign` | Benign infrastructure (also sets `isSafe`) |
| `unknown` | No reputation label available |

`malicious` is the strongest deny signal. Treat `suspicious` as a signal to
challenge or rate limit rather than an automatic deny on every route.

#### Network types

`networkTypes` lists zero or more network classifications for the IP:

| Value | Meaning |
| --- | --- |
| `hosting` | Hosting or data center network |
| `vpn` | VPN exit |
| `proxy` | Open or commercial proxy |
| `tor` | Tor exit node |
| `relay` | Privacy relay (for example Apple Private Relay) |
| `mobile` | Mobile carrier network |
| `residential` | Residential network |

An IP can belong to more than one type. These values describe the network;
they are not a deny decision on their own. Prefer the filter fields
(`ip.src.vpn`, `ip.src.hosting`, and so on) when you want to deny network
types without reading `ip.threat`.

#### Activities

`activities` lists observed abuse behaviors. An IP can have several:

| Value | Meaning |
| --- | --- |
| `brute_force` | Repeated login or credential-guessing attempts |
| `scanning` | Probing for open ports, paths, or misconfigurations |
| `exploit` | Attempts to exploit known vulnerabilities |
| `denial_of_service` | High-volume traffic aimed at overwhelming a service |
| `spam` | Bulk unwanted submissions, often through forms |
| `botnet` | Coordinated traffic from compromised machines |
| `malware` | Distribution or control of malicious software |
| `crawling` | Aggressive automated crawling |
| `fraud` | Activity consistent with fraudulent transactions |
| `post_exploitation` | Activity consistent with a host already under attacker control |
| `audit` | Security scanning consistent with auditing tooling |
| `abuse` | General abuse when no more specific activity applies |

#### Entities

`entities` lists automated client kinds associated with the IP:

| Value | Meaning |
| --- | --- |
| `crawler` | Web crawler |
| `ai_crawler` | AI training or indexing crawler |
| `ai_search` | AI search agent traffic |
| `bot` | Generic automated client |
| `scanner` | Internet-wide or security scanner |
| `compromised_device` | Device or appliance with known weaknesses, or likely botnet membership |

## Block VPN and proxy traffic

To deny only VPNs and proxies, use a narrower filter:

<Tabs syncKey="language">
<TabItem label="JavaScript / TypeScript">

```ts
filter({
  deny: ["ip.src.vpn or ip.src.proxy"],
  mode: "LIVE",
})
```

</TabItem>
<TabItem label="Python">

```py
filter_request(
    deny=["ip.src.vpn or ip.src.proxy"],
    mode=Mode.LIVE,
)
```

</TabItem>
<TabItem label="Go">

```go
arcjet.Filter(arcjet.FilterOptions{
	Deny: []string{"ip.src.vpn or ip.src.proxy"},
	Mode: arcjet.ModeLive,
})
```

</TabItem>
</Tabs>

To deny VPNs and leave proxies to another rule, use `ip.src.vpn` on its own.

Many people use VPNs for privacy or work. On a login or checkout form, that
can be a useful signal. On a public marketing page it can block real
customers. Prefer `DRY_RUN` first, then review matches in the
[Arcjet dashboard](https://console.arcjet.com).

## Deny with threat intelligence

`ip.threat` is the assessment for that IP when Arcjet has one. Check that it
exists before you read it. Then deny on the fields that match your risk
tolerance.

These patterns run in your handler after `protect()`. They are not filter
expressions.

### Deny high or critical risk

<Tabs syncKey="language">
<TabItem label="JavaScript / TypeScript">

```ts
const decision = await aj.protect(req);
const threat = decision.ip.threat;

if (
  threat &&
  !threat.isSafe &&
  (threat.riskLevel === "high" || threat.riskLevel === "critical")
) {
  return new Response("Forbidden", { status: 403 });
}
```

</TabItem>
<TabItem label="Python">

```py
decision = await aj.protect(request)
details = decision.ip_details
threat = details.threat if details else None

if (
    threat
    and not threat.is_safe
    and threat.risk_level in ("high", "critical")
):
    return JSONResponse({"error": "Forbidden"}, status_code=403)
```

</TabItem>
<TabItem label="Go">

```go
decision, err := aj.Protect(r.Context(), r)
if err != nil {
	log.Printf("arcjet: %v", err)
} else if threat := decision.IP.Threat; threat != nil && !threat.IsSafe &&
	(threat.RiskLevel == "high" || threat.RiskLevel == "critical") {
	http.Error(w, "Forbidden", http.StatusForbidden)
	return
}
```

</TabItem>
</Tabs>

`isSafe` / `is_safe` / `IsSafe` marks trusted infrastructure. Skip a denial
when it is true, even if `riskLevel` is elevated.

### Deny known abuse activity

`activities` lists observed behaviors such as `brute_force`, `scanning`,
`botnet`, and `malware`. For the full list, see
[Activities](#activities).

<Tabs syncKey="language">
<TabItem label="JavaScript / TypeScript">

```ts
const threat = decision.ip.threat;
const abusive = [
  "brute_force",
  "scanning",
  "botnet",
  "malware",
  "exploit",
  "denial_of_service",
];

if (
  threat &&
  !threat.isSafe &&
  threat.activities.some((activity) => abusive.includes(activity))
) {
  return new Response("Forbidden", { status: 403 });
}
```

</TabItem>
<TabItem label="Python">

```py
threat = decision.ip_details.threat if decision.ip_details else None
abusive = {
    "brute_force",
    "scanning",
    "botnet",
    "malware",
    "exploit",
    "denial_of_service",
}

if threat and not threat.is_safe and abusive.intersection(threat.activities):
    return JSONResponse({"error": "Forbidden"}, status_code=403)
```

</TabItem>
<TabItem label="Go">

```go
if threat := decision.IP.Threat; threat != nil && !threat.IsSafe &&
	(slices.Contains(threat.Activities, "brute_force") ||
		slices.Contains(threat.Activities, "scanning") ||
		slices.Contains(threat.Activities, "botnet") ||
		slices.Contains(threat.Activities, "malware") ||
		slices.Contains(threat.Activities, "exploit") ||
		slices.Contains(threat.Activities, "denial_of_service")) {
	http.Error(w, "Forbidden", http.StatusForbidden)
	return
}
```

</TabItem>
</Tabs>

`entities` names automated clients such as `crawler`, `ai_crawler`, `bot`,

<Tabs syncKey="language">
<TabItem label="JavaScript / TypeScript">

```ts
    threat.entities.includes("compromised_device"))

}
```

</TabItem>
<TabItem label="Python">


</TabItem>

```go
	return
}
```

</TabItem>
</Tabs>

`confidence` tells you how sure the assessment is (`low`, `medium`, or
`high`). Require `medium` or `high` before you deny on a public page.

## Inspect a decision

Use `decision.ip` when you want to customize the response instead of denying
in a filter. Check that each field is present before you read it.

<Tabs syncKey="language">
<TabItem label="JavaScript / TypeScript">

```ts
const decision = await aj.protect(req);

if (decision.isDenied()) {
  return new Response("Forbidden", { status: 403 });
}

const ip = decision.ip;

if (ip.isHosting()) {
  // Hosting and data center IPs are often automated clients.
}

if (ip.isVpn() || ip.isProxy() || ip.isTor()) {
  // Apply your policy for anonymized traffic.
}

if (ip.isAbuser()) {
  // The IP is associated with known abuse.
}

if (ip.isRelay() && ip.hasService() && ip.service === "Apple Private Relay") {
  // Apple Private Relay requires a paid iCloud subscription.
}

const threat = ip.threat;

if (threat) {
  // See Threat assessment fields for every riskLevel, reputation,
  // networkTypes, activities, and entities value.
  // threat.entityName and threat.service when Arcjet identifies them
}
```

</TabItem>
<TabItem label="Python">

```py
decision = await aj.protect(request)

if decision.is_denied():
    return JSONResponse({"error": "Forbidden"}, status_code=403)

ip = decision.ip

if ip.is_hosting():
    # Hosting and data center IPs are often automated clients.
    pass

if ip.is_vpn() or ip.is_proxy() or ip.is_tor():
    # Apply your policy for anonymized traffic.
    pass

if ip.is_abuser():
    # The IP is associated with known abuse.
    pass

if (
    decision.ip_details
    and decision.ip_details.is_relay
    and decision.ip_details.service == "Apple Private Relay"
):
    # Apple Private Relay requires a paid iCloud subscription.
    pass

details = decision.ip_details
threat = details.threat if details else None

if threat:
    # See Threat assessment fields for every risk_level, reputation,
    # network_types, activities, and entities value.
    pass
```

</TabItem>
<TabItem label="Go">

```go
decision, err := aj.Protect(r.Context(), r)
if err != nil {
	http.Error(w, "Unavailable", http.StatusServiceUnavailable)

	return

if ip.IsAbuser {
	// The IP is associated with known abuse.
}

if ip.IsRelay && ip.Service == "Apple Private Relay" {
	// Apple Private Relay requires a paid iCloud subscription.
}

if threat := ip.Threat; threat != nil {
	// See Threat assessment fields for every RiskLevel, Reputation,

}
```

## Allow a trusted relay

Apple Private Relay is the most common privacy relay. If you deny
`ip.src.relay`, you also deny those clients. To allow the relay while still
denying other anonymized networks, inspect the service name after
`protect()`:

<Tabs syncKey="language">
<TabItem label="JavaScript / TypeScript">

```ts
const decision = await aj.protect(req);

if (decision.ip.hasService() && decision.ip.service === "Apple Private Relay") {
  // Allow this client.
}

if (decision.ip.isVpn() || decision.ip.isProxy() || decision.ip.isTor()) {
  return new Response("Forbidden", { status: 403 });
}
```

</TabItem>
<TabItem label="Python">

```py
decision = await aj.protect(request)

if (
    decision.ip_details
    and decision.ip_details.service == "Apple Private Relay"
):
    # Allow this client.
    pass
elif decision.ip.is_vpn() or decision.ip.is_proxy() or decision.ip.is_tor():
    return JSONResponse({"error": "Forbidden"}, status_code=403)
```

</TabItem>
<TabItem label="Go">

```go
decision, err := aj.Protect(r.Context(), r)
if err != nil {
	log.Printf("arcjet: %v", err)
} else if decision.IP.Service == "Apple Private Relay" {
	// Allow this client.
} else if decision.IP.IsVPN || decision.IP.IsProxy || decision.IP.IsTor {
	http.Error(w, "Forbidden", http.StatusForbidden)
	return
}
```

</TabItem>
</Tabs>

A filter can express the same exception:

<Tabs syncKey="language">
<TabItem label="JavaScript / TypeScript">

```ts
filter({
  deny: [
```
