Arcjet lets you configure a list of bots to allow or deny. Pass exactly one of
`allow` or `deny` on each rule. An empty `allow` list blocks every detected
bot. To construct the list, you can specify individual bots, use categories to
allow or deny all bots in a category, or both.

If you are using TypeScript, these appear as autocomplete values for the `allow`
or `deny` options while writing your rules. In Python, the same string
identifiers are accepted on `allow` / `deny`; categories are also available
through the `BotCategory` enum. In Go, use the same strings or a
`BotCategory*` constant such as `arcjet.BotCategorySearchEngine`.

## Individual bots

The [bot
list](https://github.com/arcjet/arcjet-js/blob/main/protocol/src/well-known-bots.ts)
contains a list of known bots that Arcjet can identify.

For example:

```ts
detectBot({
   mode: "LIVE", // will block requests. Use "DRY_RUN" to log only
   // Block all bots except specific Google and Bing crawlers, and curl

      "GOOGLE_CRAWLER",
      "GOOGLE_CRAWLER_NEWS",
      "BING_CRAWLER",
      "CURL",
   ],
}),
```

## Bot categories

We provide the following categories:

- `CATEGORY:ACADEMIC`: Scrape data for research purposes
- `CATEGORY:ADVERTISING`: Scrape data for advertising and marketing purposes
- `CATEGORY:AI`: Scrape data for AI and LLM purposes
- `CATEGORY:AI_AGENT`: Fetch a page on demand for a person using an AI product.
  Every bot in this category is also in `CATEGORY:AI`
- `CATEGORY:AMAZON`: Scrape data for Amazon products and services
- `CATEGORY:APPLE`: Scrape data for Apple products and services
- `CATEGORY:ARCHIVE`: Scrape data for archival purposes
- `CATEGORY:BOTNET`: Automated behavior for malicious botnets
- `CATEGORY:FEEDFETCHER`: Request data for RSS and other feeds
- `CATEGORY:GOOGLE`: Scrape data for Google products and services
- `CATEGORY:META`: Scrape data for Meta/Facebook products and services
- `CATEGORY:MICROSOFT`: Scrape data for Microsoft products and services
- `CATEGORY:MONITOR`: Interact for monitoring purposes
- `CATEGORY:OPTIMIZER`: Interact for optimization purposes
- `CATEGORY:PREVIEW`: Request data for image and URL previews
- `CATEGORY:PROGRAMMATIC`: Interact through programming language libraries
- `CATEGORY:SEARCH_ENGINE`: Index data for search engines
- `CATEGORY:SLACK`: Scrape data for Slack products and services
- `CATEGORY:SOCIAL`: Scrape data for social media products and services
- `CATEGORY:TOOL`: Interact through command line and GUI tools
- `CATEGORY:UNKNOWN`: Known bots that cannot be classified
- `CATEGORY:VERCEL`: Scrape data for Vercel products and services
- `CATEGORY:WEBHOOK`: Automated HTTP notifications for events, such as Stripe payments
- `CATEGORY:YAHOO`: Scrape data for Yahoo products and services

The [bot
list](https://github.com/arcjet/arcjet-js/blob/main/protocol/src/well-known-bots.ts)
contains a list of categories and which bots are in each category.

`"CATEGORY:SEARCH_ENGINE"`) if you prefer not to import the enum.

### Allow AI agents and block AI crawlers

`CATEGORY:AI_AGENT` contains the AI bots that fetch a page on demand for a
person who is waiting on the answer, such as ChatGPT-User, Claude-User,
Perplexity-User, and coding agents such as Claude Code and Cursor. The rest of
`CATEGORY:AI` collects pages ahead of time, for model training or for an AI
search index.

Every bot in `CATEGORY:AI_AGENT` is also in `CATEGORY:AI`, so a rule that
denies `CATEGORY:AI` also blocks AI agents. To block AI crawlers and let AI
agents through, use an `allow` list that includes `CATEGORY:AI_AGENT`. An
`allow` list blocks every other detected bot, so also include the other
categories that you rely on, such as `CATEGORY:SEARCH_ENGINE`. Some AI
search crawlers, such as OAI-SearchBot and YouBot, are also in
`CATEGORY:SEARCH_ENGINE`, so allowing that category lets them through:

```ts
detectBot({

   // Block all bots except search engines and AI agents
   allow: [
      "CATEGORY:SEARCH_ENGINE", // Google, Bing, etc
      "CATEGORY:AI_AGENT", // ChatGPT-User, Claude-User, coding agents, etc
   ],
}),
```

Coding agents such as Claude Code fetch pages from the developer's own
computer, not from the AI company's servers. Arcjet can't verify them against
the company's published IP addresses, so Arcjet reports these bots as neither
verified nor spoofed.

Only configured categories are checked for performance reasons. Each detected
bot must be compared to a category, so the worst case performance is
`count(detectedBot) * count(configuredCategories)`.

We're continuously evaluating bots to decide whether any need reclassifying. If
we determine enough bots exist for a new category, we'll consider adding new
ones. If you need a specific category, open an issue on the
[arcjet/well-known-bots](https://github.com/arcjet/well-known-bots) repository.

## Custom bots

If a bot that is not on our list signs its requests with Web Bot Auth, you can
allow or deny it by its key directory URL, for example
`SIGNED_BOT:https://bot.example.com/.well-known/http-message-signatures-directory`.
For details, see <Link.Page href="/bot-protection/web-bot-auth">Verify signed bots with Web Bot Auth</Link.Page>.

To block a particular bot that is not on our list and doesn't sign its
requests, you can use <Link.Page href="/filters">Arcjet Filters</Link.Page>. For how to
block custom bots, see the <Link.Page href="/blueprints/malicious-traffic">Malicious traffic</Link.Page> blueprint.

### Known bots structure

The identifiers on the bot list are generated from [a collection of known
bots](https://github.com/arcjet/well-known-bots) which includes details of their
owner and any variations.

We welcome contributions to the
[arcjet/well-known-bots](https://github.com/arcjet/well-known-bots) repository,
whether you're adding new bots or updating detection patterns. After a change is
merged, Arcjet updates its pinned copy of the catalog. The update reaches Arcjet
Cloud when Arcjet deploys it, and the SDK's local detection in the next SDK
release. The SDK runs local bot detection in the Arcjet
WebAssembly module bundled with the SDK, so new patterns must be compiled into
the module as part of the release process.

For instructions on how to contribute to our bot detection, read the
repository's [README.md](https://github.com/arcjet/well-known-bots/blob/main/README.md).

### Unknown bots

If a bot is detected but cannot be identified as a known bot, Arcjet labels it
`UNKNOWN_BOT`. This is separate from the `CATEGORY:UNKNOWN` category, which is
for bots that cannot be classified into any category but can still be identified
as a specific bot. You can see a list of these named, but unclassified bots in
the [bot
list](https://github.com/arcjet/arcjet-js/blob/24d2ee3139f277499ef3cb65f1f1eab998647819/protocol/well-known-bots.ts#L990).

Detections returned as `UNKNOWN_BOT` happen if the bot is new or hides itself.
It's a bot with no name. Arcjet uses various techniques to detect these bots,
including analyzing request patterns and tracking IP addresses.

If you configure an `allow` rule and do not include `UNKNOWN_BOT`, then Arcjet
blocks detected bots that it cannot identify. This is the default behavior to
protect against new and rapidly evolving bots.

If you want to be more permissive and only block known, named bots, you can
include `UNKNOWN_BOT` in your `allow` rules.
