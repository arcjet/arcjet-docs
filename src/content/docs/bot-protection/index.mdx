Bot protection identifies the automated clients that request your site, such as
search engine crawlers, AI agents, AI crawlers, scrapers, and attack tools, and
lets you decide which ones to allow. Arcjet bot protection runs inside your
application as a `detectBot` rule, so each decision can depend on the route, the
signed-in user, and your own business logic.

## What bot protection is for

Most sites see two kinds of automated traffic that need different answers.

### AI agents acting for people

AI agents fetch pages, fill in forms, and call APIs for a person who is waiting
on the result. ChatGPT, Claude, Perplexity, Google's agents, and agentic
browsers all send this kind of traffic. Blocking every agent can turn away a
real customer. Letting every agent through can expose account actions to
automation that you didn't plan for.

Arcjet tells an AI agent apart from an AI crawler that collects pages for model
training, and reports how sure it is. You can allow agents, block crawlers, and
give agents a response that suits them. For more information, see
<Link.Page href="/bot-protection/ai-agents">Detect AI agents</Link.Page>.

### Malicious bots

Scrapers copy your content and pricing, credential stuffing tools try stolen
passwords, signup bots create fake accounts, and some clients pretend to be
Googlebot to get past your rules. These bots often hide behind a browser
`User-Agent` header and cloud or proxy networks.

Arcjet blocks bots that you don't need, catches clients that fake a good bot's
identity, and flags automated browsers and risky networks. For more
information, see <Link.Page href="/bot-protection/malicious-bots">Block malicious bots</Link.Page>.

## How Arcjet identifies a bot

Any client can claim to be any bot, so no single signal is enough. Arcjet
combines several sources of evidence and reports which one established the
result.

### The well-known bots list

Arcjet matches the `User-Agent` header against an open source list of more than
850 known bots, such as `GOOGLE_CRAWLER` and `OPENAI_CRAWLER_USER`, in 24
categories, such as `CATEGORY:SEARCH_ENGINE`, `CATEGORY:AI`, and
`CATEGORY:AI_AGENT`. You allow or deny bots by ID or by category, and TypeScript
autocompletes both.

The list is maintained in
[`arcjet/well-known-bots`](https://github.com/arcjet/well-known-bots), and
contributions are welcome. For the categories and how to use them, see
<Link.Page href="/bot-protection/identifying-bots">Bot identity, IDs, and categories</Link.Page>.

### Verification by IP address and reverse DNS

A `User-Agent` header is easy to fake. Many operators publish the IP address
ranges that their bots use, and Arcjet checks the request's IP address against
them. For operators that publish a hostname pattern, Arcjet looks up the
hostname for the IP address and confirms that it belongs to the operator, such
as a Googlebot address that resolves to a Google hostname.

When a request claims to be a bot but comes from somewhere else, Arcjet marks
it as spoofed. For more information, see <Link.Page href="/bot-protection/reference#bot-verification">Bot verification</Link.Page>.

### Web Bot Auth signatures

Some bots and AI agents sign each request with a key that the operator
publishes on its own domain. Arcjet verifies the signature, which identifies
the operator even when the agent runs a standard browser and sends a browser
`User-Agent` header. For more information, see <Link.Page href="/bot-protection/web-bot-auth">Verify signed bots with Web Bot Auth</Link.Page>.

### Advanced signals

A script on your pages runs checks in the browser that detect automation, such
as a headless browser or a browser that a framework drives. Arcjet reads the
result from a cookie on the next request, so bots that pass as real browsers on
the server side can still be caught. For more information, see
<Link.Page href="/bot-protection/advanced-signals">Advanced bot signals</Link.Page>.

### IP threat intelligence

Arcjet labels each client IP address with its network type, such as hosting,
VPN, proxy, or Tor, and, when it has one, a threat assessment with a risk level.
Bot detection uses this data to name known crawlers and botnets by their IP
address, and your code can read the same data from the decision to block or
challenge risky networks. For more information, see
<Link.Page href="/ip-threat-intelligence">IP threat intelligence</Link.Page>.

## Bot identity and evidence

When Arcjet Cloud detects a bot, the result includes one primary bot identity:
which bot Arcjet thinks sent the request, what kind of client it is, such as an
AI agent or an AI crawler, and the evidence for it. From strongest to weakest,
the evidence levels are as follows:

1. `SIGNATURE`: A Web Bot Auth signature verified against the operator's keys.
1. `IP`: The IP address is in the operator's published ranges, Arcjet's IP data
   names the bot, or reverse DNS confirmed it.
1. `FINGERPRINT`: The advanced signals browser checks failed.
1. `UNVERIFIED`: Arcjet matched the `User-Agent` header or IP reputation, and
   couldn't verify it.

The evidence level lets you trust a signed or IP-verified agent more than a
`User-Agent` claim. The JavaScript, Python, and Go SDKs expose the bot
identity. For every field, see
<Link.Page href="/bot-protection/identifying-bots#bot-identity">Bot identity</Link.Page>.

## Bot rules in your application code

Bot protection at the network or CDN layer often gives you a fixed set of rules.
Arcjet runs in your application, where you know who the user is, what plan they
pay for, and which routes are sensitive. You can allow a bot on your marketing
pages and deny it on your API, or relax a rule for a signed-in customer.

Bot protection is also part of
<Link.Page href="/ai-protection/abuse-protection">AI Abuse Protection</Link.Page>.
Automated clients that call AI features inflate token costs and use up per-user
budgets. Combine bot protection with
<Link.Page href="/rate-limiting">rate limiting</Link.Page> to control who can
use those features and how much.

No bot detection system is fully accurate. Combine bot protection with
<Link.Page href="/rate-limiting">rate limiting</Link.Page>,
<Link.Page href="/filters">filters</Link.Page>, and
<Link.Page href="/shield">Shield</Link.Page> so that one missed detection
doesn't leave a route open.

### Configure bot rules without code changes

You can also configure bot rules as
<Link.Page href="/remote-rules">remote rules</Link.Page> from the Arcjet
Console or through the <Link.Page href="/mcp-server">MCP server</Link.Page>.
Remote rules apply to the whole site with no code change or redeployment, which
helps when you need to block a bot category during an incident. Developers can
keep route-specific bot rules in code, while a security team uses remote rules
for site-wide changes.

:::tip[Using the MCP server]
Use the <Link.Page href="/mcp-server">Arcjet MCP server</Link.Page> to monitor
bot traffic. Call `analyze-traffic` to see top IP addresses and denial rates,
`get-anomalies` to detect sudden changes in bot patterns, or
`get-security-briefing` for an overview of threats and recommendations.
:::
