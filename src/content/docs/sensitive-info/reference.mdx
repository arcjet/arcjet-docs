Arcjet Sensitive Information Detection stops clients from sending you data
that you don't want to handle, such as personally identifiable information
(PII). The SDK rule runs detection in your own environment with the on-device
[Rampart](#on-device-detection-with-rampart) named-entity recognition (NER)
model. It detects names, addresses, and government or financial identifiers, as
well as structured types such as email addresses and card numbers. The text it
scans never leaves your environment.

## Configuration

You configure sensitive information detection with a list of entity types to
allow or to deny. The two lists are mutually exclusive:

- With `allow`, Arcjet denies any detected type that the list doesn't name.
- With `deny`, Arcjet denies only the types that the list names.

Add one or more sensitive information rules to the `arcjet` client. Create them
with `sensitiveInfo(...)` in JavaScript / TypeScript,
`detect_sensitive_info(...)` in Python, or
`arcjet.SensitiveInfo(arcjet.SensitiveInfoOptions{...})` in Go. The lists are
`allow` and `deny` in JS and Python, and `Allow` and `Deny` in Go.

Set `backend` to the [Rampart backend](#on-device-detection-with-rampart):
`rampart()` in JS and Python, or the `Backend` that you create with
`rampart.New` in Go.

## On-device detection with Rampart

Sensitive information detection runs on-device. It pairs the
[Rampart](https://huggingface.co/nationaldesignstudio/rampart) NER model, which
understands context, with deterministic recognizers for structured types. The
rule detects names, addresses, and government or financial identifiers, as
well as email addresses, card numbers, IP addresses, and phone numbers. For the
full list, see [Entity types](#entity-types).

The model weights ship with the package, so nothing is fetched at runtime and
the text you scan stays in your environment. JavaScript and Python run a
~15&nbsp;MB quantized ONNX model. Go embeds the same ~15&nbsp;MB of weights in a
nested module and runs inference in pure Go, with no cgo or ONNX runtime.

Install the Rampart package alongside your Arcjet SDK. In Python, it ships as
the `sensitive-info-rampart` extra of the `arcjet` package. In Go, it's a nested
module that bundles the model weights:

<Tabs syncKey="language">
<TabItem label="JavaScript / TypeScript">

```shell
npm install @arcjet/sensitive-info-rampart
```

</TabItem>
<TabItem label="Python">

```shell
pip install "arcjet[sensitive-info-rampart]"
```

</TabItem>
<TabItem label="Go">

```shell
go get github.com/arcjet/arcjet-go/sensitiveinfo/rampart
```

</TabItem>
</Tabs>

Then import `rampart` and pass it as the rule's `backend`. Create the Go
backend once at startup with `rampart.New` and reuse it. List the entity types
to detect in `allow` or `deny`:

### Model accuracy and performance

Rampart is compact enough to run inline on each request: a ~14.7&nbsp;MB
artifact with ~18.5M parameters, quantized to 4-bit weights, and a 512-token
context window. Longer text is scanned in overlapping windows. On the Node.js
CPU runtime, median (p50) inference is **~6.6&nbsp;ms**, and **~3.9&nbsp;ms** on
WebGPU (set `device: "webgpu"` in the JS SDK). The Python backend runs on
[ONNX Runtime](https://onnxruntime.ai/) and uses the CPU by default. To use a
different accelerator, set the `providers` option. In Go, create the backend
once with `rampart.New` and reuse it.

On the model author's held-out benchmark, Rampart recalls **~98%** of private
terms across the seven Latin-script languages it supports: English, Spanish,
French, German, Italian, Portuguese, and Dutch.

Accuracy depends on the input. Keep the following trade-offs in mind:

- **Non-Latin scripts** (for example Chinese, Japanese, Korean, Arabic, Hindi,
  or Cyrillic) have much lower recall – the model is trained on Latin-script
  text.
- **Government or financial identifiers without a checksum** (passports,
  licenses, case numbers) are recognized less reliably than the structured types
  the deterministic recognizers validate, such as emails and card numbers.
- **Latency** – inference runs synchronously in the request path, so it adds to
  the response time of each request that the rule scans.

These figures come from the
[Rampart model card](https://huggingface.co/nationaldesignstudio/rampart), which
has the full per-language breakdown, calibration data, and limitations.

### Rampart options

The `rampart()` factory (JS and Python) or `rampart.New` (Go) accepts these
options:

<Tabs syncKey="language">
<TabItem label="JavaScript / TypeScript">

```ts
import { defaultRecognizers, rampart } from "@arcjet/sensitive-info-rampart";

rampart({
  // Execution device (default: "cpu"). Set to "webgpu" to use a GPU when the
  // runtime supports it.
  device: "webgpu",
  // Minimum confidence score for a model token to count (default: 0.5).
  threshold: 0.6,
  // Largest input to scan, in characters (default: 100_000). The rule denies
  // longer input without scanning it. Lower it to bound latency, or raise it
  // to accept longer text.
  maxInputChars: 100_000,
  // Deterministic recognizers to run alongside the model (default:
  // `defaultRecognizers`). This is the extension point for custom detection –
  // add a recognizer that returns matched spans. Pass `[]` to rely on the
  // model alone.
  recognizers: [
    ...defaultRecognizers,
    (value) => {
      // Return an array of `{ start, end, type }` spans.
      return [];
    },
  ],
});
```

</TabItem>
<TabItem label="Python">

The `rampart()` factory takes an optional `RampartOptions`:

```py
from arcjet_sensitive_info_rampart import (
    RampartOptions,
    default_recognizers,
    rampart,
)

rampart(
    RampartOptions(
        # Minimum confidence score for a model token to count (default: 0.5).
        threshold=0.6,
        # ONNX Runtime execution providers (default: ("CPUExecutionProvider",)).
        # Set this to use a GPU or other accelerator supported by your ONNX
        # Runtime install.
        providers=("CPUExecutionProvider",),
        # Largest input to scan, in characters (default: 100,000). The rule
        # denies longer input without scanning it. Lower it to bound latency,
        # or raise it to accept longer text.
        max_input_chars=100_000,
        # Deterministic recognizers to run alongside the model (default:
        # `default_recognizers`). This is the extension point for custom
        # detection – add a recognizer that returns matched spans. Pass () to
        # rely on the model alone.
        recognizers=(
            *default_recognizers,
            lambda value: [],  # Return a list of DetectedSpan(start, end, type).
        ),
        # Directory containing the model files (default: the bundled models).
        model_path=None,
    )
)
```

</TabItem>
<TabItem label="Go">

`rampart.New` takes `rampart.Options`. Inference is pure Go (no cgo). There is
no `device` or ONNX provider option:

```go
backend, err := rampart.New(rampart.Options{

	// Largest input to scan, in characters (default: 4096). The rule denies

	// can afford the extra latency.
	MaxInputChars: 4096,
	// Deterministic recognizers run alongside the model (default:
	// rampart.DefaultRecognizers). Pass an empty non-nil slice to rely on the
	// model alone. Phone numbers are left to the model because their digit
	// shape overlaps with financial and government identifiers.
	// Recognizers: []rampart.Recognizer{},
})
```

### Long input

Rampart scans text on the request path, so longer text takes longer to scan.
To keep that cost predictable, each SDK sets a maximum length, which you can
change:

| SDK        | Default limit      | Option            |
| ---------- | ------------------ | ----------------- |
| JavaScript | 100,000 characters | `maxInputChars`   |
| Python     | 100,000 characters | `max_input_chars` |
| Go         | 4,096 characters   | `MaxInputChars`   |

A live rule denies text longer than the limit without scanning any of it, so
nothing past the limit goes through unchecked. A rule in dry run mode reports
the denial without blocking. The limit applies to `protect()`, to the local
sensitive information rule in <Link.Page href="/guards">Arcjet Guards</Link.Page>, and to a `LOCAL` input in an
agent guard policy. JavaScript counts UTF-16 code units, and Python and Go
count Unicode code points.

With `protect()`, the denial has an error reason instead of a sensitive
information reason, because Arcjet didn't detect anything. The examples on this
page block it with their catch-all denial. To return a clearer response, check
for the error reason: `decision.reason.isError()` in JavaScript,
`decision.reason_v2.type == "ERROR"` in Python, or `decision.Reason.IsError()`
in Go:

```ts
if (decision.isDenied() && decision.reason.isError()) {
  // The text is longer than the backend's scan limit.
  return Response.json({ error: "Message too long" }, { status: 413 });
}
```

With Guards, the rule result is a denial with no detected entity types.

Choose a limit that fits your latency budget. Each window of about 480
characters is one inference pass, so a higher limit raises the worst-case scan
time for a request. The limit must be a positive whole number, and there's no
setting that turns it off. Also cap the request body size in your server or
framework, so your application doesn't read an oversized body into memory.

On-device detection suits typical request fields. For longer text, you have
the following options:

- **Raise the limit** when the extra latency fits your budget.
- **Use a server input.** Send the text as a `SERVER` input to the server-side
  sensitive information detector in an
  <Link.Page href="/guards/remote-policies#detectors">agent guard policy</Link.Page>, which screens values up to about
  100&nbsp;KB on Arcjet's servers. Arcjet allows up to 3 seconds to screen a
  value over 2&nbsp;KB, and a live rule fails closed if the scan doesn't
  finish. Set the client timeout above 3 seconds (the default is 2), so the
  client doesn't stop waiting first, and deny the request when
  `hasFailedOpen()` is true.
- **Split the text** into parts, for text longer than about 100&nbsp;KB, and
  screen each part in its own `guard()` call. Each call screens up to two
  `SERVER` inputs longer than 2&nbsp;KB.

To detect protected health information (PHI), always use the server-side
detector. On-device detection doesn't detect the PHI types. For more
information, see
<Link.Page href="/sensitive-info/phi">Detect protected health information (PHI)</Link.Page>.

In JavaScript and Python, the model loads on first use and is reused for every
later request. In Go, `rampart.New` loads and dequantizes the weights, so
create the backend once at startup and reuse it. It's safe for concurrent use.

To detect your own entity types, add a recognizer. See
[Custom entity detection](#custom-entity-detection).

### Bundlers and runtimes

In JavaScript and Python, the Rampart backend loads a native ONNX runtime and
reads its model weights from disk at runtime. This affects where it runs and how
you build your application:

- It requires a server runtime with filesystem and native-addon access. In JS
  that means Node.js, Bun, or Deno – it does **not** run on edge runtimes. In
  Python it runs anywhere the SDK does (Python 3.10+).
- A server build must not bundle it, or the runtime fails to locate the model
  weights.

In Go, inference is pure Go. The weights are compiled into the nested module,
so there's no ONNX runtime, native addon, or extra file for a bundler to miss.
An application that imports the module adds about 15&nbsp;MB of weights to its
binary.

In Python, the backend depends on
[ONNX Runtime](https://onnxruntime.ai/) (`onnxruntime`), which the
`arcjet[sensitive-info-rampart]` extra installs. Inference is synchronous, so
it adds to the response time of each request that the rule scans, with either
the `arcjet()` or the `arcjet_sync()` client.

For Next.js, mark the package and its native dependencies as
[server external packages](https://nextjs.org/docs/app/api-reference/config/next-config-js/serverExternalPackages),
so that Next.js loads them from `node_modules` at runtime instead of bundling
them. Run each route handler that uses the backend on the Node.js runtime, which
is the default, rather than the Edge runtime:

```js
// next.config.js
/** @type {import('next').NextConfig} */
const nextConfig = {
  serverExternalPackages: [
    "@arcjet/sensitive-info-rampart",
    "@huggingface/transformers",
    "onnxruntime-node",
  ],
};

module.exports = nextConfig;
```

```ts
// app/api/arcjet/route.ts
export const runtime = "nodejs";
```

## Decision

To evaluate your rules, call the `protect` function.

<SlotByFramework>
  <NestJsGuardDecision slot="nest-js" />
</SlotByFramework>

The function returns a `Promise` that resolves to an `ArcjetDecision` object
with the following properties:

- `id` (`string`) – The unique ID for the request. Use it to look up the
  request in the Arcjet Console. Decisions that involve the Arcjet cloud API
  have the prefix `req_`, and decisions made locally have the prefix `lreq_`.
- `conclusion` (`ArcjetConclusion`) – The overall conclusion from evaluating
  every configured rule. To follow Arcjet's recommended action, use this
  property.
- `reason` (`ArcjetReason`) – More detail about the conclusion.
- `results` (`ArcjetRuleResult[]`) – The result of each rule that ran.
- `ip` (`ArcjetIpDetails`) – Arcjet's analysis of the client IP address. For
  more information, see the SDK reference.

To check whether a sensitive information rule denied the request, use
`decision.isDenied()` and `decision.reason.isSensitiveInfo()` (JS) /
`decision.is_denied()` and `decision.reason_v2.type == "SENSITIVE_INFO"`
(Python) / `decision.IsDenied()` and `decision.Reason.IsSensitiveInfo()` (Go).

To see what each rule found, iterate through the results:

## Entity types

For every entity type that Arcjet detects, grouped by category with its
taxonomy version and where Arcjet detects it, see
<Link.Page href="/sensitive-info/entity-types">Sensitive information entity types</Link.Page>.
The SDK detects the version 1 types with Rampart. List any of them in `allow` or
`deny`. Each one is an `ArcjetSensitiveInfoType` in JS, a
`SensitiveInfoEntityType` in Python, and an `arcjet.EntityType` in Go.

To list every type at once, use `rampartEntities` (JS), `rampart_entities`
(Python), or `rampart.Entities()` (Go).

### Structured type matching

The default recognizers match these structured types with deterministic,
validated patterns.

#### Card numbers

Arcjet detects card numbers of 13 to 19 digits when the final digit is a valid
[Luhn](https://en.wikipedia.org/wiki/Luhn_algorithm) check digit. The values
`4242424242424242`, `4000 0566 5566 5556`, and `3782-8224-6310005` match, but
`4242424242424241` doesn't. Spaces and dashes are ignored, because people often
group the digits.

#### Email addresses

The values `alice@example.com` and `bob.smith@subdomain.example.com` match, but
`alice.example.com` doesn't.

#### IP addresses

Arcjet detects IPv4 and IPv6 addresses. The values `127.0.0.1` and `::1` match.

#### Social Security numbers

Arcjet detects US Social Security numbers in the dashed form, such as
`123-45-6789`.

#### URLs

Arcjet detects URLs that start with `http://`, `https://`, or `www.`. The model
also detects URLs from context.

#### Phone numbers

The Rampart model detects phone numbers from context. The default recognizers
don't include a phone number pattern, because a run of digits can also be a
bank account, routing number, or government identifier, and a pattern can't
tell which one it is.

## Custom entity detection

To detect patterns that the default recognizers don't cover, add your own
recognizer to the Rampart `recognizers` option. A recognizer receives the full
text and returns the spans it matched, each with a start offset, an end offset,
and an entity type. Recognizer results take precedence over the model where
they overlap.

Keep the default recognizers in the list unless you want to replace them. The
following example adds a recognizer that reports IBANs as `BANK_ACCOUNT`:

  <CustomDetectBun slot="bun" />
  <CustomDetectGo slot="go" />
  <CustomDetectNestJs slot="nest-js" />

Offsets are UTF-16 code unit indexes in JS, code point indexes in Python, and
byte offsets in Go – the indexes each language's regular expression matches
return.

## Error handling

By default, Arcjet fails open, so a service issue or misconfiguration doesn't
block your users. The SDK times out and fails open after 2,000&nbsp;ms. Most
responses take 20&nbsp;ms to 30&nbsp;ms.

If a rule hits an error, Arcjet returns an `ERROR` result for that rule. The
`message` property on the result explains what went wrong. If every other rule
that ran returned `ALLOW`, the overall conclusion is `ERROR`.

Sensitive information detection protects data, so deny the request when the
decision is errored, unless your application can accept data that Arcjet didn't
screen. The quick start examples fail closed this way. The following example
logs the error and shows where to fail closed:
