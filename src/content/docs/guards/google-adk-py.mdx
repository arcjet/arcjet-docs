[Google Agent Development Kit](https://google.github.io/adk-docs/)
(ADK) Python `LlmAgent` workflows call authored tools from
`run_async`. Arcjet Guard sits at those boundaries so a policy can
allow or deny the action before a side effect runs.

<FrameworkPrimer />

This adapter is the Python `arcjet[google-adk]` extra plus
`guard_tool`, `guard_plugin`, and `google_adk_context`. It is not
the JavaScript `@arcjet/guard/google-adk/v2` adapter. It isn't
Google GenAI. Don't wrap these tools with
`@arcjet/guard/google-adk/v2` or `@arcjet/guard/vercel-ai/v7`.

## Install

Until `arcjet.guard.google_adk` is published, pin `arcjet` to
[`679423c9`](https://github.com/arcjet/arcjet-py/commit/679423c9f5f6db2ad3ca573088faabd862a8587b).
Published `arcjet` 1.0.0 on PyPI does not include this extra.

```bash
pip install "arcjet[google-adk] @ git+https://github.com/arcjet/arcjet-py@679423c9f5f6db2ad3ca573088faabd862a8587b"
```

`arcjet[google-adk]` depends on `google-adk>=2.0.0,<3`. CPython
3.10 or later.

Import helpers from `arcjet.guard.google_adk`:

```py
from arcjet.guard.google_adk import (
    google_adk_context,
    guard_plugin,
    guard_tool,
)
```

Launch one client at module scope:

```py
from arcjet.guard import launch_arcjet

arcjet = launch_arcjet(key=ARCJET_KEY)
```

Use `launch_arcjet_sync` with Flask, Django, or other sync code.

## Helpers

Pick the surface that matches what you hold when the effect runs:

| You have | Use | Needs | Blocks a call? |
| --- | --- | --- | --- |
| Any Python callable | `guard_action` / `guard_action_sync` | `arcjet` | Yes |
| An `LlmAgent.before_tool_callback` | `guard_tool` | `arcjet[google-adk]` | Yes |
| A Runner `plugins` list | `guard_plugin` | `arcjet[google-adk]` | Yes |
| A session or conversation ID you already have | `google_adk_context` | `arcjet[google-adk]` | No |

`guard_tool` returns an `LlmAgent.before_tool_callback`
`(tool, args, tool_context)`. Assign it on
`LlmAgent(before_tool_callback=...)`. On `DENY`, or when Guard
cannot be evaluated and `on_guard_error` is `"deny"`, the callback
returns a skip dict with `arcjetDenied` (`ArcjetDenialResult`).
The original tool never runs. Return `None` to execute. Empty
`{}` also skips – never return `{}` to allow. The callback does
not raise.

`guard_plugin` is the Runner-wide gate. Pass it first on
`InMemoryRunner` or `Runner` `plugins`. Its
`before_tool_callback` uses the same skip dict. PluginManager is
first-win: the first plugin that returns a dict skips remaining
plugins and the agent callback. Return `None` to execute. The
callback does not raise.

`google_adk_context` reads a caller-owned ID you pass:
`correlation_id`, then `session_id`, then `conversation_id`.
Camel-case aliases `correlationId`, `sessionId`, and
`conversationId` are also read. It never mints an ID. It never
reads `trace_id` or `traceId`. It never reads an ADK-generated
`invocation_id`. It never reads `tool_context.session.id` or
`session.id`. If the caller did not pass an ID, then the call is
uncorrelated rather than joined to a generated ID.

There is no inbound helper. Screen user text with a direct
`guard()` call before `runner.run_async`. There is no approval
helper.

Don't call `create_agent_context` inside an ADK callback. Don't
also wrap these tools with `@arcjet/guard/google-adk/v2` or
`@arcjet/guard/vercel-ai/v7`.

## Helper options

`guard_tool` and `guard_plugin` share this contract:

| Option | Helpers | Description |
| --- | --- | --- |
| `action` | `guard_tool`, `guard_plugin` | Guard label and capture name. Use `resource.verb` in the past tense. A string, or a function of `{ tool_name, input }`. Defaults to `tool.invoked`. |
| `rules` | `guard_tool`, `guard_plugin` | SDK rules, or a function of `{ tool_name, input }`. Omit to submit none. The guard call still happens. |
| `metadata` | `guard_tool`, `guard_plugin` | Nested JSON, or a function of the same input as `rules`. |
| `session_id` | `guard_tool`, `guard_plugin` | Caller-owned fallback when the object you pass to `google_adk_context` does not carry one. A string, or a function of the same input as `rules`. Prefer putting the ID on `run_async` and the context helper. |
| `on_guard_error` | `guard_tool`, `guard_plugin` | `"deny"` (default) or `"allow"`. |

Inbound screening uses direct `guard()`, which takes `label` (not
`action`) and fails open. See the following section.

## Denial payload

On `DENY` the original tool never runs. The payload shape is one
`ArcjetDenialResult`. The envelope is the skip dict from
`before_tool_callback`:

- `guard_tool` and `guard_plugin` return that object to skip the
  tool.
- `None` executes the tool.
- Empty `{}` also skips. The helpers never return `{}`.

It is not a raise. It is not `require_confirmation` or
`request_confirmation`. A raise is the wrong envelope. `None` on
error executes the tool.

```json
{
  "arcjetDenied": true,
  "reason": "RATE_LIMIT",
  "message": "Arcjet denied this call (RATE_LIMIT). It may be retried after 30 seconds.",
  "retryable": true,
  "retryAfterSeconds": 30
}
```

Only rate-limit denials set `retryable: true` and include
`retryAfterSeconds`. Other reasons tell the model not to retry.

When Guard is unavailable and `on_guard_error` is `"deny"`, the
model receives `reason: "ERROR"`, `retryable: true`, and
`retryAfterSeconds: 5`. Fail closed always returns that deny dict
on error. It never raises. It never returns `None` on error.

## Run a guarded `run_async`

Screen inbound text and pick one tool-call gate. This example
puts `guard_plugin` first on the Runner `plugins` list:

```py
from google.adk.agents import LlmAgent
from google.adk.runners import InMemoryRunner
from google.adk.tools import FunctionTool
from google.genai import types
from arcjet.guard import (
    DetectPromptInjection,
    LocalDetectSensitiveInfo,
    TokenBucket,
    launch_arcjet,
)
from arcjet.guard.google_adk import (
    google_adk_context,
    guard_plugin,
)

arcjet = launch_arcjet(key=ARCJET_KEY)

lookup_limit = TokenBucket(
    refill_rate=10,
    interval_seconds=60,
    max_tokens=10,
    bucket="lookups",
)
detect_pii = LocalDetectSensitiveInfo()
inbound = DetectPromptInjection()


def lookup_order(order_number: str, note: str) -> dict:
    """Look up an order by number."""
    return {
        "order_number": order_number,
        "note": note,
        "status": "shipped",
    }


agent = LlmAgent(
    name="order_agent",
    model="gemini-flash-latest",
    instruction="Look up orders with lookup_order.",
    tools=[FunctionTool(lookup_order)],
)


async def run_agent(conversation_id: str, user_text: str):
    app_context = {"session_id": conversation_id}
    derived = google_adk_context(app_context)

    decision = await arcjet.guard(
        label="message.received",
        rules=[inbound(user_text)],
        correlation_id=derived.correlation_id,
    )
    if decision.conclusion == "DENY" or decision.has_failed_open():
        raise RuntimeError("message blocked")

    def plugin_rules(call):
        if call["tool_name"] != "lookup_order":
            return []
        return [
            lookup_limit(key=call["input"]["order_number"], requested=1),
            detect_pii(call["input"]["note"]),
        ]

    runner = InMemoryRunner(
        agent=agent,
        app_name="orders",
        plugins=[
            guard_plugin(
                guard=arcjet,
                action="order.looked-up",
                session_id=conversation_id,
                on_guard_error="deny",
                rules=plugin_rules,
            )
        ],
    )

    return runner.run_async(
        user_id=conversation_id,
        session_id=conversation_id,
        new_message=types.Content(
            role="user",
            parts=[types.Part.from_text(text=user_text)],
        ),
    )
```

## Screen user text before `run_async`

There is no inbound hook, so there is no inbound helper. Put
prompt-injection and other inbound rules in the application before
`runner.run_async`.

Direct `guard()` fails open, so an `ALLOW` is not proof the rules
ran. Gate inbound on `decision.has_failed_open()` if this call site
must fail closed. `guard_tool` and `guard_plugin` already default
to that.

On `DENY`, don't call `run_async`.

```py
from arcjet.guard import DetectPromptInjection, launch_arcjet
from arcjet.guard.google_adk import google_adk_context

arcjet = launch_arcjet(key=ARCJET_KEY)
inbound = DetectPromptInjection()
app_context = {"session_id": conversation_id}
derived = google_adk_context(app_context)

decision = await arcjet.guard(
    label="message.received",
    rules=[inbound(user_text)],
    correlation_id=derived.correlation_id,
)
if decision.conclusion == "DENY" or decision.has_failed_open():
    raise RuntimeError("message blocked")
```

## Gate an `LlmAgent` with `guard_tool`

`guard_tool` is the agent `before_tool_callback`. Assign it on
`LlmAgent(before_tool_callback=...)`. The callback denies by
returning a skip dict with `arcjetDenied` without calling the
tool. Return `None` to execute. Policy sits on
`before_tool_callback` only.

Wrapping a `FunctionTool` handler is the wrong gate. The callback
is the skip point.

```py
from google.adk.agents import LlmAgent
from google.adk.tools import FunctionTool
from arcjet.guard.google_adk import guard_tool
from arcjet.guard import launch_arcjet

arcjet = launch_arcjet(key=ARCJET_KEY)

agent = LlmAgent(
    name="order_agent",
    model="gemini-flash-latest",
    instruction="Look up orders with lookup_order.",
    tools=[FunctionTool(lookup_order)],
    before_tool_callback=guard_tool(
        guard=arcjet,
        action="order.looked-up",
        session_id=conversation_id,
        rules=lambda call: (
            [lookup_limit(key=call["input"]["order_number"], requested=1)]
            if call["tool_name"] == "lookup_order"
            else []
        ),
    ),
)
```

Don't attach `guard_tool` and `guard_plugin` on the same run if
you want one evaluation. A plugin `None` (allow) still runs the
agent callback.

## Human approval is not a policy gate

`require_confirmation` and `request_confirmation` are
human-in-the-loop (HITL) confirmation. They are not a policy gate.
Same trap as LangChain JS `humanInTheLoopMiddleware`, Strands
`event.interrupt()`, Genkit `interrupt()`, OpenAI `needs_approval`,
Mastra `requireApproval`, TanStack `needsApproval`, and Claude
`can_use_tool`. There is no approval helper. Don't wrap HITL as
Guard. Don't use ADK `SecurityPlugin` as the Arcjet policy gate.
Don't deny by pausing for a human. Policy sits on
`before_tool_callback` only.

On `DENY` the original tool never runs, so the inner handler never
runs a side effect. `guard_tool` and `guard_plugin` skip with a
dict that includes `arcjetDenied`. Don't raise. Don't call
`request_confirmation`. Don't pause for a human to approve a
denied call. Scan free-text args (a note, reason, or body). An
opaque `order_number` or tool-call ID does not trip email, phone,
card, or IP detection, so don't pass it to
`LocalDetectSensitiveInfo`. That helper runs on a local ML model
backend.

## Deny Runner-wide via `guard_plugin`

`guard_plugin` is the Runner `plugins` gate. Put it first in the
plugin list. `before_tool_callback` uses the first dictionary that
a plugin returns. If another plugin returns a dict first, then
Guard never runs.

The hook denies by returning a skip dict with `arcjetDenied`
without calling the tool. That dict is the `ArcjetDenialResult`.
Return `None` to execute. Policy sits on `before_tool_callback`
only.

This is not Google GenAI. This is not JavaScript ADK. Don't pass
`guardPlugin` from `@arcjet/guard/google-adk/v2` to a Python
Runner.

```py
from google.adk.runners import InMemoryRunner
from arcjet.guard.google_adk import guard_plugin
from arcjet.guard import launch_arcjet

arcjet = launch_arcjet(key=ARCJET_KEY)

runner = InMemoryRunner(
    agent=agent,
    app_name="orders",
    plugins=[guard_plugin(guard=arcjet, session_id=conversation_id)],
)
```

## Correlation

`google_adk_context` reads a caller-owned ID from the object you
pass: `correlation_id` first, then `session_id`, then
`conversation_id`. Camel-case aliases are also read. It never mints
an ID. It never reads `trace_id` or `traceId`. It never reads an
ADK-generated `invocation_id`. It never reads
`tool_context.session.id` or `session.id`. ADK can generate a
session or invocation ID when you omit one. That auto-generated
value is not a correlation source. Don't derive an ID from it.
Don't mint one. If the caller did not pass an ID, then the call is
uncorrelated rather than joined to a generated ID.

A run that pauses on `request_confirmation` resumes through a later
`run_async`. Pass the same caller-owned ID on that resume call so
later Guard decisions stay on the Sequence that started it. The
confirmation payload is not a correlation source.

Put the same ID on `run_async(session_id=...)` and as `session_id`
on `guard_tool` or `guard_plugin`.

```py
app_context = {"session_id": conversation_id}
derived = google_adk_context(app_context)

await arcjet.guard(
    label="message.received",
    correlation_id=derived.correlation_id,
)

await runner.run_async(
    user_id=conversation_id,
    session_id=conversation_id,
    new_message=types.Content(
        role="user",
        parts=[types.Part.from_text(text=user_text)],
    ),
)
```

## What not to use

- There is no inbound helper. Screen prompt injection before
  `runner.run_async`.
- There is no approval helper. `require_confirmation` and
  `request_confirmation` are human HITL confirmation, not policy.
- Don't use ADK `SecurityPlugin` as the Arcjet policy gate.
- Don't treat this adapter as Google GenAI.
- Don't treat this adapter as JavaScript ADK.
- Don't turn a deny into `request_confirmation` or a human
  approval pause.
- Don't mint a correlation ID. Don't use `trace_id`, `traceId`, an
  ADK-generated `invocation_id`, `tool_context.session.id`, or
  `session.id`. If the caller did not pass an ID, then leave the
  call uncorrelated.
- Don't put Arcjet after another `before_tool_callback` plugin.
  The first deny dict wins.
- Don't raise from `before_tool_callback` to signal a denial.
- Don't return `None` on a Guard error. Fail closed always
  returns the deny dict.
- Don't return `{}` to allow. ADK treats an empty mapping as skip.
- Don't wrap a `FunctionTool` handler as the gate. Use
  `guard_tool` or `guard_plugin`.
- Don't wrap these tools with `@arcjet/guard/google-adk/v2` or
  `@arcjet/guard/vercel-ai/v7`.
- Don't use this page for the JavaScript Google ADK adapter. For
  that adapter, see
  <Link.Page href="/guards/google-adk">Google ADK agent guard</Link.Page>.

## Common patterns

### Rate limit a tool by a trusted ID

Key the bucket on a trusted identifier such as `order_number`.
Don't key it on free-text user input.

```py
lookup_limit = TokenBucket(
    refill_rate=10,
    interval_seconds=60,
    max_tokens=10,
    bucket="lookups",
)

runner = InMemoryRunner(
    agent=agent,
    app_name="orders",
    plugins=[
        guard_plugin(
            guard=arcjet,
            action="order.looked-up",
            rules=lambda call: (
                [lookup_limit(key=call["input"]["order_number"], requested=1)]
                if call["tool_name"] == "lookup_order"
                else []
            ),
        )
    ],
)
```

### Scan a free-text note for sensitive information

Scan a note, reason, or body. An opaque `order_number` does not
trip email, phone, card, or IP detection, so don't pass it to
`LocalDetectSensitiveInfo`.

```py
from arcjet.guard import LocalDetectSensitiveInfo, TokenBucket
from arcjet.guard.google_adk import guard_plugin

lookup_limit = TokenBucket(
    refill_rate=10,
    interval_seconds=60,
    max_tokens=10,
    bucket="lookups",
)
detect_pii = LocalDetectSensitiveInfo()

runner = InMemoryRunner(
    agent=agent,
    app_name="orders",
    plugins=[
        guard_plugin(
            guard=arcjet,
            action="order.looked-up",
            rules=lambda call: (
                [
                    lookup_limit(
                        key=call["input"]["order_number"],
                        requested=1,
                    ),
                    detect_pii(call["input"]["note"]),
                ]
                if call["tool_name"] == "lookup_order"
                else []
            ),
        )
    ],
)
```

## Fail-closed default

`guard_tool` and `guard_plugin` default to
`on_guard_error="deny"`. If Guard cannot be evaluated, then
`before_tool_callback` returns the deny dict instead of calling
the tool. It never raises. It never returns `None` on that path.

Set `on_guard_error="allow"` only when executing without a complete
security decision is acceptable, such as a read-only lookup. Direct
`guard()` still fails open. For more information about fail-open
versus fail-closed behavior, see
<Link.Page href="/guards/reference#availability-and-fail-behavior">Availability and fail behavior</Link.Page>.
