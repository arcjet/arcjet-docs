[Genkit](https://genkit.dev/) flows call `ai.generate()` / `chat.send()` and
authored `ai.defineTool` handlers. Arcjet Guard sits at those boundaries so a
remote policy can allow or deny the action before a side effect runs.

<FrameworkPrimer />

Vercel AI SDK, Python LangChain, Eve, Mastra, LangGraph, OpenAI Agents, and
Claude wrappers are on
<Link.Page href="/guards/framework-integrations">Framework integrations</Link.Page>.

This adapter is Genkit JS `generate()` / `chat.send()` plus authored
`ai.defineTool`. There is no inbound hook. Middleware `model` is not Guard.
Don't also wrap these tools with `@arcjet/guard/vercel-ai/v7`.

## Install

Install the Guard SDK and Genkit:

```bash
npm install @arcjet/guard genkit
```

Import helpers from the versioned path `@arcjet/guard/genkit/v1`. There is
no unversioned alias. `@arcjet/guard/genkit` does not resolve. The version
segment is Genkit's major. `genkit` (`>=1.0 <2`) is an optional peer. The
integration requires Node.js 22 or later. Until `@arcjet/guard/genkit/v1` is
published, the import lives on the unpublished Guard adapter branch, not in
the published `@arcjet/guard` package on npm.

Launch one client at module scope:

```ts
import { launchArcjet } from "@arcjet/guard";

export const arcjet = launchArcjet({ key: process.env.ARCJET_KEY! });
```

## Helpers

The integration exposes three surfaces:

- `guardTool()` wraps an authored `ai.defineTool` action. On `DENY` the
  original handler never runs, so the tool never runs a side effect. Return
  a structured `arcjetDenied` object if that object survives `outputSchema`.
  Don't turn a deny into `ToolInterruptError` or
  `finishReason: 'interrupted'`.
- `guardMiddleware()` is a `generateMiddleware` `tool` hook. Pass it on
  `ai.generate()` so `generate()`-wide tool attempts hit Guard. MCP and
  filesystem-injected tools skip an unwrapped handler. Hosted or injected
  tools are not a `defineTool` deny.
- `genkitContext()` reads a caller-owned ID: `correlationId`, then
  `sessionId`, then `conversationId`, then a caller-owned flow or run ID.
  It never mints an ID. It never reads `traceId` or OpenTelemetry.

There is no `guardInbound`. There is no inbound hook. Screen user text with a
direct `guard()` call before `ai.generate()` or `chat.send()`. There is no
`guardApproval`.

Never call `createAgentContext` inside a Genkit callback. Don't also wrap
these tools with `@arcjet/guard/vercel-ai/v7`.

## Helper options

| Option | Helpers | Description |
| --- | --- | --- |
| `action` | `guardTool`, `guardMiddleware` | Guard label and capture name. Use `resource.verb` in the past tense. |
| `rules` | `guardTool`, `guardMiddleware` | SDK rules, or a function of the parsed tool input. Omit to submit none. |
| `metadata` | `guardTool`, `guardMiddleware` | Nested JSON, or a function of the same input as `rules`. |
| `onGuardError` | `guardTool`, `guardMiddleware` | `"deny"` (default) or `"allow"`. |

Inbound screening uses direct `guard()`, which takes `label` (not `action`)
and fails open. See the following section.

## Screen user text before `generate()`

There is no inbound hook, so there is no `guardInbound`. Put
prompt-injection and other inbound rules in the application before
`ai.generate()` or `chat.send()`.

Middleware `model` is not Guard. It does not screen user text.

Direct `client.guard({ label, rules, ...genkitContext(...) })` is the
inbound pattern. Act on that decision. Direct `guard()` fails open, so an
`ALLOW` is not proof the rules ran. Gate inbound on
`decision.hasFailedOpen()` if this call site must fail closed. `guardTool`
and `guardMiddleware` already default to that.

On `DENY`, don't call `generate()` / `send()`.

```ts
import { detectPromptInjection } from "@arcjet/guard";
import { genkitContext } from "@arcjet/guard/genkit/v1";
import { arcjet } from "./arcjet.js";

const inbound = detectPromptInjection();

const decision = await arcjet.guard({
  label: "message.received",
  rules: [inbound(userText)],
  ...genkitContext({ sessionId: conversationId }),
});

if (decision.conclusion === "DENY" || decision.hasFailedOpen()) {
  throw new Error("message blocked");
}

await ai.generate({ prompt: userText });
```

## Human approval is not a policy gate

`interrupt()` / `defineInterrupt` / `@genkit-ai/middleware` `toolApproval` /
`restartTool` are human-in-the-loop (HITL) confirmation. They are not a
policy gate. Same trap as Mastra `requireApproval`, Claude `canUseTool`,
LangGraph `interrupt()`, and OpenAI `needsApproval`. There is no
`guardApproval`. Don't wrap them as Guard.

Use `guardTool` for authored `ai.defineTool` handlers you own.

On `DENY` the original handler never runs. Return a structured
`arcjetDenied` object if that object survives `outputSchema`. Don't throw
`ToolInterruptError` and don't set `finishReason: 'interrupted'` to signal
a policy deny. Scan free-text args (a note, reason, or body). An opaque
`orderNumber` or tool-call ID will not trip email / phone / card / IP, so
don't pass it to `localDetectSensitiveInfo`. That helper runs on a local
ML model backend.

```ts
import { z } from "genkit";
import { guardTool } from "@arcjet/guard/genkit/v1";
import { tokenBucket, localDetectSensitiveInfo } from "@arcjet/guard";
import { arcjet } from "./arcjet.js";

// `ai` is the instance `genkit()` returned.

const lookupLimit = tokenBucket({
  bucket: "lookups",
  refillRate: 10,
  intervalSeconds: 60,
  maxTokens: 10,
});
// Factory then text. Same shape as `detectPromptInjection()(text)`.
const detectPii = localDetectSensitiveInfo();

export const lookupOrder = guardTool(
  arcjet,
  ai.defineTool(
    {
      name: "lookup_order",
      description: "Look up an order by number",
      inputSchema: z.object({
        orderNumber: z.string(),
        note: z.string(),
      }),
    },
    async ({ orderNumber, note }) => ({
      orderNumber,
      note,
      status: "shipped",
    }),
  ),
  {
    action: "order.looked-up",
    rules: (input) => [
      lookupLimit({ key: input.orderNumber, requested: 1 }),
      detectPii(input.note),
    ],
  },
);
```

## Deny inside `ai.defineTool` via `guardTool`, and generate()-wide via `guardMiddleware`

`guardTool` wraps an authored `ai.defineTool` handler. That handler is the
only local side effect this adapter can stop on a single action.

`guardMiddleware` is a `generateMiddleware` `tool` hook. Pass it on
`ai.generate()` so tool attempts during that `generate()` hit Guard.

MCP and filesystem-injected tools skip an unwrapped handler. Hosted or
injected tools are not a `defineTool` deny. `returnToolRequests: true`
still hits `guardTool` if the caller invokes the wrapped action.

```ts
import { guardMiddleware } from "@arcjet/guard/genkit/v1";
import { tokenBucket } from "@arcjet/guard";
import { arcjet } from "./arcjet.js";

const generateLimit = tokenBucket({
  bucket: "generate-tools",
  refillRate: 20,
  intervalSeconds: 60,
  maxTokens: 20,
});

const result = await ai.generate({
  prompt: userText,
  tools: [lookupOrder],
  use: [
    guardMiddleware(arcjet, {
      action: "tool.invoked",
      rules: [generateLimit({ key: conversationId, requested: 1 })],
    }),
  ],
});
```

## Correlation

`genkitContext` reads a caller-owned ID. Preference order is
`correlationId`, then `sessionId`, then `conversationId`, then a
caller-owned flow or run ID. It never mints an ID. It never reads
`traceId` or OpenTelemetry. If nothing is a valid 1-256 printable-ASCII
string, the call is uncorrelated rather than joined to a generated ID.

```ts
const ctx = { sessionId: conversationId };

await arcjet.guard({
  label: "message.received",
  ...genkitContext(ctx),
});
```

## What not to use

- There is no `guardInbound`. Screen prompt injection before
  `ai.generate()` or `chat.send()`.
- There is no `guardApproval`. `interrupt()` / `defineInterrupt` /
  `@genkit-ai/middleware` `toolApproval` / `restartTool` are human HITL
  confirmation, not policy.
- Don't treat middleware `model` as Guard.
- Don't turn a deny into `ToolInterruptError` or
  `finishReason: 'interrupted'`.
- Don't expect an unwrapped MCP or filesystem-injected tool to hit
  `guardTool`. Use `guardMiddleware` on that `generate()`.
- Don't read `traceId` or OpenTelemetry for correlation.
- Don't call `createAgentContext` inside a Genkit callback.
- Don't also wrap these tools with `@arcjet/guard/vercel-ai/v7`.
- Don't import `@arcjet/guard/genkit`. The path is
  `@arcjet/guard/genkit/v1`.

## Common patterns

- **Prompt injection before `generate()`:** Direct `guard()` with
  `detectPromptInjection()(userText)` and a `hasFailedOpen()` check.
- **Rate limit plus PII on a tool:** `guardTool` with `tokenBucket` keyed
  on a trusted ID, plus `localDetectSensitiveInfo()` on a free-text
  `note`.
- **`generate()`-wide tools:** `guardMiddleware` as a `generateMiddleware`
  `tool` hook on `ai.generate()`.
- **Correlate the run:** Pass a caller-owned `sessionId` or
  `conversationId` to `genkitContext`. Don't read `traceId`.
