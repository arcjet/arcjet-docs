AI frameworks normally pass a model's generated arguments directly to a tool's
`execute` or `invoke` function. Arcjet's framework integrations add a security
checkpoint between those two steps, so SDK rules evaluate every tool attempt
before the tool can create a side effect.

Use an integration when you want to protect tools without writing decision
handling around every function. The wrapper preserves the framework's normal
tool definition and result flow and calls `guard()` with a stable `label`
before the tool executes.

## Vercel AI SDK

The JavaScript integration supports Vercel AI SDK v7 through the versioned
`@arcjet/guard/vercel-ai/v7` export.

```ts
import { launchArcjet } from "@arcjet/guard";
import {
  aiToolsContext,
  createAgentContext,
  guardTool,
} from "@arcjet/guard/vercel-ai/v7";
import { generateText, tool } from "ai";
import { z } from "zod";

const arcjet = launchArcjet({ key: process.env.ARCJET_KEY! });

export async function runAgent(prompt: string) {
  const sendEmail = guardTool(
    arcjet,
    tool({
      description: "Send an email",
      inputSchema: z.object({ to: z.string(), body: z.string() }),
      execute: ({ to, body }) => emailProvider.send({ to, body }),
    }),
    {
      label: "email.sent",
    },
  );

  const tools = { sendEmail };
  const context = createAgentContext();

  return generateText({
    model,
    prompt,
    tools,
    toolsContext: aiToolsContext(context, tools),
  });
}
```

The wrapped tool must have an `execute` function and cannot already declare a
`contextSchema`, because Arcjet uses that slot for agent context. On a policy
denial, the tool does not execute and the model receives an `ArcjetDenialResult`.

## LangChain

The Python integration wraps synchronous or asynchronous LangChain tools.
Install the optional dependency:

```bash
pip install "arcjet[langchain]"
```

```py
from arcjet.guard import launch_arcjet
from arcjet.guard.langchain import guard_tool
from langchain_core.tools import tool

arcjet = launch_arcjet(key=ARCJET_KEY)


@tool
async def send_email(to: str, body: str) -> str:
    """Send an email."""
    await email_provider.send(to=to, body=body)
    return "sent"


guarded_send_email = guard_tool(
    guard=arcjet,
    tool=send_email,
    label="email.sent",
)
```

Use the asynchronous Guard client with `ainvoke()` and the synchronous client
with `invoke()`.

## Vercel Eve

Eve agents can have zero authored tools. OpenAPI and MCP connections have no
local `execute`, so the enforcement point is `guardApproval()` on the
connection. Screen inbound channel text with `guardInbound()` before the agent
starts. Hooks are observe-only (handlers return `void`).

See the <Link.Page href="/guards/vercel-eve">Vercel Eve agent guard</Link.Page>
for inbound screening, connection approvals, and lifecycle hooks.

## Mastra

Mastra has no `guardInbound` (channels already hit `processInput`) and no
`guardApproval` (`requireApproval` is human HITL). Screen inbound text with
`guardProcessor`. Gate authored tools with `guardTool`. Gate MCP/workspace
tools you did not wrap with `guardHooks` (`beforeToolCall` can deny).

See the <Link.Page href="/guards/mastra">Mastra agent guard</Link.Page>
for processors, tools, and hooks.

## Denials and availability

The wrappers default to fail closed when Guard is unavailable:

- Vercel AI does not execute the tool and returns a retryable denial result to
  the model with reason `ERROR`.
- LangChain raises `ArcjetToolUnavailableError`. A policy denial raises
  `ArcjetToolDeniedError`, or follows the wrapped tool's `handle_tool_error`
  behavior when configured.
- Vercel Eve helpers default to `onGuardError: "deny"`. On a channel, `"allow"`
  is a legitimate choice because failing closed stops the agent answering.
- Mastra helpers default to `onGuardError: "deny"`. `"allow"` is a legitimate
  choice on the inbound processor because failing closed stops the agent
  answering.

Set `onGuardError: "allow"` in JavaScript or `on_guard_error="allow"` in Python
only when executing without a complete security decision is acceptable.

See <Link.Page href="/guards/reference#availability-and-fail-behavior">Availability and fail behavior</Link.Page>
for the direct client and wrapper differences.
