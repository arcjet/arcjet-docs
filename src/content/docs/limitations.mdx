No security product is perfect and Arcjet is no exception. Here are some things
to be aware of when building your application with Arcjet.

## Your application receives traffic

Network-based security products block traffic before it hits your application.
This works well for high-volume network attacks, so leave those to the DDoS
protection built into your hosting platform.

Arcjet is designed to integrate into your application and understand more about
the request context. This lets Arcjet apply the right rules, and lets you
customize the response based on the signals that Arcjet provides. You can also
show useful error messages rather than returning generic status codes.

For example, it is difficult for network based security products to distinguish
between a free user making excessive API calls and your largest paying customer
performing important queries. Likewise, you may want to manually review users
signing up from behind a proxy who have disposable email addresses, but allow
those with business emails to sign up instantly.

We believe application context is critical, and that is what Arcjet is designed
for. It also means that your application receives more traffic than if the
network had blocked it.

## Shield analysis does not use the request body

<Link.Page href="/shield">Arcjet Shield</Link.Page> analysis is based on the
request headers and query parameters. To minimize false positives
and achieve low-latency responses, Shield analysis happens in the background on
the Arcjet platform after a request has been reported to our API. For
<Link.Page href="/privacy">privacy</Link.Page> we do not send the request body
to our API, so it cannot be used for analysis.

Local request body analysis is on the Arcjet roadmap for Shield.

## How Arcjet handles limits

Each detection feature accepts text up to a hard limit. Arcjet denies text over
the limit instead of passing it unchecked, so padding a request past the limit
can't skip detection. A rule in dry run mode doesn't block, but still reports
the code.

When Arcjet can't complete a check, for example because of a timeout, the rule
fails open and the decision reports the error, so a service issue doesn't block
your application. To fail closed instead, check `decision.hasFailedOpen()` with
`guard()` or `decision.isErrored()` with `protect()`, and deny the request
yourself. A live rule in an <Link.Page href="/guards/remote-policies">agent guard policy</Link.Page> fails closed when it can't be evaluated.

## Detection input limits

The following table lists the hard limit for each detection feature:

| Feature                    | Limit                       | When you exceed it                                                                |
| -------------------------- | --------------------------- | --------------------------------------------------------------------------------- |
| Prompt injection detection | 128&nbsp;KiB of text per call | A live rule denies the request. With `guard()`, the rule result carries `AJ1131`. |
| Content moderation         | 128&nbsp;KiB of text per call | A live rule denies the call, and the rule result carries `AJ1141`.                |

Content moderation evaluates the first 60&nbsp;KB of the text. For longer
text, Arcjet adds the warning `AJ1142` to `decision.warnings`
(`decision.Warnings` in Go), and the rest of the text isn't moderated. Text
larger than 128&nbsp;KiB returns an error in dry run mode and a denial in live
mode. To moderate all of the text, split it into parts and moderate each one.

## Rules per guard call

A `guard()` call evaluates at most 50 rules. Arcjet doesn't run the rules after
the 50th, reports them as not run, and adds `AJ1003` to `decision.warnings`
(`decision.Warnings` in Go). Rules that don't run can't deny, so keep each call
to 50 rules or fewer, and split a larger set across calls.

## Agent guard policy input limits

The inputs that a guard call sends to an agent guard policy have the following
limits. Going over any of them invalidates the call's inputs, so every live
rule in the policy fails closed with `AJP1003`.

| Limit                    | Value                                     |
| ------------------------ | ----------------------------------------- |
| Inputs per call          | 64                                        |
| Server string input      | About 100&nbsp;KB                         |
| Server string list input | 256 items, and about 100&nbsp;KB in total |

Quotes, backslashes, and line breaks each count as more than one byte toward
these limits, so text with many of them reaches the limit sooner.

Threat detection scores at most 30 distinct public hosts per call. A call that
names more fails a live rule closed with `AJP1009`.

## Limits on agent activity

Capture events, OpenTelemetry ingest, and the Arcjet Console views built on them
have the following limits:

- **Capture is best effort.** The SDK queues capture events in memory and sends
  them in batches. It never retries a failed batch, so an event can be lost, for
  example when a serverless runtime freezes before the batch is sent. Don't make
  application behavior depend on a capture call. For more information, see
  <Link.Page href="/guards/capture#delivery">Delivery</Link.Page>.
- **OpenTelemetry ingest uses HTTP only.** Arcjet accepts the `http/protobuf`
  and `http/json` OTLP protocols. It doesn't accept OTLP over gRPC. For more
  information, see
  <Link.Page href="/observe#send-opentelemetry-data-to-arcjet">Send OpenTelemetry data to Arcjet</Link.Page>.
- **A Sequence needs capture events.** A Sequence is the capture events that
  share a correlation ID. Decisions with a correlation ID appear on the Sequence
  for that ID, but decisions alone don't form a Sequence.
- **An AI summary needs a single key.** The Arcjet Console summarizes a Sequence
  only when all of its activity arrives under one key, either one actor key or
  the project key alone. If two keys use the same correlation ID, the Sequence
  has no AI summary.
- **Log retention limits how far back you can look.** Your plan's log retention
  sets how far back you can view captures, decisions, and Sequences. For more
  information, see
  <Link.Page href="/privacy#data-retention">Data retention</Link.Page>.
