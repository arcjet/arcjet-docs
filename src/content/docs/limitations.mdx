Every security product makes trade-offs. This page explains the ones Arcjet
makes, so you can design your application around them.

## Your application receives traffic

Network security products block traffic before it reaches your application.
That works well for high-volume network attacks, so leave those to the DDoS
protection built into your hosting platform.

Arcjet runs inside your application, where it can see the request context. It
applies the right rules for each route and user, and gives you signals to shape
the response. You can show a helpful error message instead of a generic status
code.

For example, a network product struggles to tell a free user making excessive
API calls from your largest paying customer running important queries. Likewise,
you might want to review sign-ups that come from a proxy with a disposable email
address, but let sign-ups with a business email through straight away.

Application context makes these decisions possible. The trade-off is that your
application receives traffic that a network product would have blocked earlier.

## Shield analysis uses headers and query parameters

<Link.Page href="/shield">Arcjet Shield</Link.Page> analyzes the request headers
and query parameters. To keep responses fast and false positives low, Shield
runs its analysis in the background on the Arcjet platform after the SDK
reports the request. For <Link.Page href="/privacy">privacy</Link.Page>, the
SDK doesn't send the request body to Arcjet, so Shield doesn't analyze it.

Local request body analysis is on the Arcjet roadmap for Shield.

## How Arcjet handles limits

Arcjet is secure by default. Each detection feature accepts text up to a hard
limit, and Arcjet denies text over that limit instead of letting it through
unchecked. Padding a request past the limit doesn't skip detection. A rule in
dry run mode reports the same code without blocking, so you can see the effect
before you enforce it.

Service issues are handled differently. When Arcjet can't complete a check, for
example because of a timeout, the rule fails open and the decision reports the
error. This keeps a temporary service issue from blocking your users. To fail
closed instead, check `decision.hasFailedOpen()` with `guard()` or
`decision.isErrored()` with `protect()`, and deny the request yourself. A live
rule in an <Link.Page href="/guards/remote-policies">agent guard policy</Link.Page> fails closed when it can't be evaluated.

## Detection input limits

The following table lists the hard limit for each detection feature:

| Feature                         | Limit                                                    | When you exceed it                                                                  |
| ------------------------------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Prompt injection detection      | 128&nbsp;KiB of text per call                            | A live rule denies the request. With `guard()`, the rule result carries `AJ1131`.   |
| Content moderation              | 128&nbsp;KiB of text per call                            | A live rule denies the call, and the rule result carries `AJ1141`.                  |
| On-device sensitive information | 100,000 characters in JavaScript and Python, 4,096 in Go | A live rule denies the request without scanning the text. You can change the limit. |

Content moderation evaluates the first 60&nbsp;KB of the text. Longer text
under the hard limit is still moderated on that first part, and Arcjet adds the
warning `AJ1142` to `decision.warnings` (`decision.Warnings` in Go) so you know.
The warning doesn't change the decision. To moderate all of the text, split it
into parts and moderate each one.

## Rules per guard call

A `guard()` call evaluates up to 50 rules. If you pass more, Arcjet reports the
rules after the first 50 as not run and adds `AJ1003` to `decision.warnings`
(`decision.Warnings` in Go). A rule that doesn't run can't deny, so keep each
call to 50 rules or fewer and split a larger set across calls.

## Agent guard policy input limits

An agent guard policy evaluates the inputs that each guard call sends. The
following table lists the limits on those inputs. If a call goes over any of
them, Arcjet treats its inputs as invalid, and every live rule in the policy
fails closed with `AJP1003`.

| Limit                    | Value                                     |
| ------------------------ | ----------------------------------------- |
| Inputs per call          | 64                                        |
| Server string input      | About 100&nbsp;KB                         |
| Server string list input | 256 items, and about 100&nbsp;KB in total |

Quotes, backslashes, and line breaks each count as more than one byte toward
these limits, so text with many of them reaches the limit sooner.

Threat detection scores up to 30 distinct public hosts per call. A call that
names more fails a live rule closed with `AJP1009`.

## Limits on agent activity

Capture events, OpenTelemetry ingest, and the Arcjet Console views built on
them work within the following limits:

- **Capture is best effort.** The SDK queues capture events in memory and sends
  them in batches, without retrying a failed batch. An event can be lost, for
  example when a serverless runtime freezes before the batch is sent, so don't
  make application behavior depend on a capture call. For more information, see
  <Link.Page href="/guards/capture#delivery">Delivery</Link.Page>.
- **OpenTelemetry ingest uses HTTP.** Arcjet accepts the `http/protobuf` and
  `http/json` OTLP protocols. It doesn't accept OTLP over gRPC. For more
  information, see
  <Link.Page href="/observe#send-opentelemetry-data-to-arcjet">Send OpenTelemetry data to Arcjet</Link.Page>.
- **A Sequence is built from capture events.** A Sequence is the capture events
  that share a correlation ID. Decisions with that correlation ID appear on the
  Sequence, but decisions alone don't form one.
- **An AI summary needs a single key.** The Arcjet Console summarizes a Sequence
  when all of its activity arrives under one key: either one actor key, or the
  project key alone. If two keys use the same correlation ID, the Sequence has
  no AI summary.
- **Log retention sets how far back you can look.** Your plan's log retention
  sets how far back you can view captures, decisions, and Sequences. For more
  information, see
  <Link.Page href="/privacy#data-retention">Data retention</Link.Page>.
